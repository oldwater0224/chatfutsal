# 프로필 수정 기능명세서

> GitHub Issue: #58

## 1. 개요

가입 후 닉네임(`displayName`)을 바꿀 수 있게 한다. 지금은 가입 시 입력한 이름을 바꿀 방법이 없다.

### 범위

| 항목 | 상태 |
|---|---|
| 닉네임 변경 (`/mypage/profile`) | **이번 작업** |
| `userService.ts` 신설 (`users` 문서 쓰기 경로) | **이번 작업** |
| 실력 수준(레벨) 표시 | **보류** — 저장 위치·설계를 더 검토한 뒤 결정 (7장) |
| 포지션 | **제외** — 필요하지 않음 |
| 프로필 이미지 업로드 | **제외** — Firebase Storage 설정이 필요해 별도 과제 |

`User` 타입은 바꾸지 않는다.

## 2. 화면

### 2-1. 진입

`/mypage` → **계정** 섹션 → "프로필 수정" → `/mypage/profile`

### 2-2. `/mypage/profile`

```
┌ SubHeader: 프로필 수정 ┐
│ 닉네임                  │
│ [ 현재 닉네임        ]  │
│ 2~12자                  │
│ (오류 메시지)           │
├─────────────────────────┤
│ [        저장        ]  │  ← 바뀐 게 없거나 형식이 틀리면 비활성
└─────────────────────────┘
```

- 비로그인 → `/login`으로 이동 (`/mypage`와 같은 방식)
- 저장 성공 → `/mypage`로 이동. `/mypage`가 다시 마운트되며 `users` 문서를 새로 읽으므로 바뀐 이름이 바로 보인다
- 저장 실패 → 입력값은 유지하고 오류 메시지를 표시

## 3. 닉네임 규칙

`src/lib/services/userRules.ts`의 순수 함수 `validateDisplayName(raw, current)`로 판정한다. 화면과 서비스가 같은 함수를 쓴다.

| 조건 | 결과 |
|---|---|
| 앞뒤 공백 제거 후 저장 | `"  풋살러 "` → `"풋살러"` |
| 2자 미만 / 12자 초과 | 오류: "닉네임은 2~12자로 입력해주세요." |
| 현재 닉네임과 같음 | 오류는 아니지만 저장할 것이 없음 (`unchanged`) → 저장 버튼 비활성 |

글자 수는 `Array.from()`으로 센다 (이모지 등 서로게이트 쌍을 한 글자로 계산).
가입 화면에는 아직 같은 규칙이 없다. 가입 시점 검증은 이번 범위가 아니다.

## 4. 저장 흐름

```
/mypage/profile 저장
  → validateDisplayName() 통과
  → userService.updateDisplayName(authUser, name)
      1. updateDoc(users/{uid}, { displayName })   ← Firestore
      2. updateProfile(authUser, { displayName })  ← Firebase Auth
```

**두 곳을 모두 바꾸는 이유:** 앱이 닉네임을 두 출처에서 읽는다.

| 출처 | 쓰는 곳 |
|---|---|
| Firestore `users/{uid}.displayName` (`useAuth().userData`) | 마이페이지, 모집글 작성(`authorName`), 참가 신청(`applicantName`), 모집글에서 채팅 시작, 다른 사용자 프로필, 사용자 검색 |
| Firebase Auth `user.displayName` (`useAuth().user`) | 헤더 아바타, 채팅 메시지(`senderName`), 프로필에서 채팅 시작 |

Firestore를 먼저 쓴다. 다른 사용자에게 보이는 원본이기 때문이다. Auth 갱신이 실패하면 오류를 표시하고, 다시 저장하면 두 곳이 모두 맞춰진다.

부수 효과: 카카오 로그인 사용자는 커스텀 토큰으로 로그인해서 Auth `displayName`이 비어 있다 (헤더 "U", 채팅 "사용자"로 표시). 닉네임을 한 번 저장하면 Auth에도 이름이 들어가 이 표시가 바로잡힌다.

## 5. 이미 저장된 이름 (비정규화)

`displayName`은 다음 문서에 복사되어 있다. **채팅방만 갱신하고 나머지는 그대로 둔다** (이슈 #58의 1안 + 채팅방 예외).

| 위치 | 필드 | 변경 후 |
|---|---|---|
| `chatRooms` | `participantNames[uid]` | **갱신** (5-1) |
| `recruitPosts` | `authorName` | 기존 글은 옛 이름, 새 글부터 새 이름 |
| `applications` | `applicantName` | 기존 신청은 옛 이름, 새 신청부터 새 이름 |
| `messages` | `senderName` | 기존 메시지는 옛 이름, 새 메시지부터 새 이름 (채팅 화면에는 표시되지 않음) |

일괄 갱신(2안)을 전부 택하지 않은 이유: 보안 규칙상 `applications`는 다른 사용자 문서라 클라이언트에서 고칠 수 없다. 표시 시점 조회(3안)는 목록마다 `users` 읽기가 늘고 페이지네이션과 맞지 않는다.

한계: 모집글·신청 목록에는 옛 이름과 새 이름이 섞여 보일 수 있다. 필요해지면 서버 작업으로 일괄 갱신하는 방안을 검토한다.

### 5-1. 채팅방 이름

채팅 목록과 채팅방 상단은 `participantNames[상대 uid]`로 상대 이름을 보여준다. 1:1 대화에서 옛 이름이 보이면 다른 사람으로 오해할 수 있어 갱신한다.

| 시점 | 동작 |
|---|---|
| 닉네임 저장 | `chatService.updateMyNameInChatRooms` — 내가 참여한 방(`participants array-contains uid`)마다 내 항목을 갱신. **방마다 따로 써서**(`Promise.allSettled`) 한 방이 실패해도 나머지는 반영된다. 실패는 로그만 남기고 닉네임 변경은 성공으로 처리 |
| 기존 방에서 채팅 다시 시작 | `startChat`이 저장된 내 이름이 현재 닉네임과 다르면 바로잡는다 (위에서 빠진 방 보정). 실패해도 채팅은 연다 |
| 새 방 생성 | 내 이름은 `users` 문서 닉네임, 모집글에서 시작할 때 상대 이름은 `authorName` 대신 `users` 문서의 현재 닉네임 |
| 채팅방 화면 | `getDoc` 대신 `onSnapshot`으로 구독해 대화 중 상대가 이름을 바꿔도 바로 반영 |

채팅 목록은 원래 `onSnapshot`으로 구독 중이라 별도 작업이 없다.

## 6. 보안 규칙

`users/{userId}`는 본인만 `create, update`할 수 있다 (변경 없음).

`chatRooms` update에 조건을 하나 추가했다. 참여자는 `participantNames`에서 **내 항목만**, **내 `users` 문서의 현재 닉네임과 같은 값으로만** 바꿀 수 있다 (`get()` 읽기 1회 추가). 다른 필드와 함께 바꿀 수 없다.

```
function changesOnlyOwnName() {
  return changedOnly(['participantNames'])
    && request.resource.data.participantNames.diff(resource.data.participantNames)
         .affectedKeys().hasOnly([request.auth.uid])
    && request.resource.data.participantNames[request.auth.uid]
         == get(/databases/$(database)/documents/users/$(request.auth.uid)).data.displayName;
}
```

```
match /users/{userId} {
  allow read: if signedIn();
  allow create, update: if isUser(userId);
}
```

규칙은 필드 형식을 검사하지 않으므로 닉네임 길이 제한은 클라이언트 검증뿐이다.
`users` 문서는 로그인 사용자 전체가 읽을 수 있으므로 민감한 필드를 추가하지 않는다.

## 7. 보류: 실력 수준(레벨)

모집글에는 이미 `beginner / amateur / semipro / pro` 레벨(`LEVEL_LABELS`, `LEVEL_COLORS`)이 있다.
사용자 프로필에 레벨을 표시하려면 값을 어디에 둘지(사용자가 직접 고르는 값 / 활동에서 파생 등)부터 정해야 해서 이번 작업에서 뺐다. 설계가 정해지면 이 문서에 이어서 기록한다.
