# 푸시 알림(FCM) 기능명세서

> 관련: #16 (인앱 알림) — 이번 작업은 그 위에 웹 푸시를 더한다

## 1. 개요

인앱 알림(`notifications` 컬렉션)이 생길 때 받는 사람의 브라우저로 **웹 푸시**를 보낸다.
앱을 닫아 두었거나 다른 탭을 보고 있어도 새 메시지·신청 결과를 알 수 있게 한다.

### 범위

| 항목 | 상태 |
|---|---|
| 웹 푸시 (Chrome·Edge·Firefox·macOS Safari) | **이번 작업** |
| 마이페이지에서 푸시 켜기 | **이번 작업** |
| 알림 종류별 수신 설정 | 제외 — 전부 받거나 전부 끄기 |
| iOS Safari | 제외 — 홈 화면에 추가한 PWA에서만 웹 푸시가 되므로 매니페스트 작업이 먼저 필요 |
| 네이티브 앱 푸시 | 제외 |

## 2. 전체 흐름

```
[받는 사람 브라우저]                         [서버 /api/push]                     [FCM]
마이페이지 "푸시 알림" 켜기
 → 알림 권한 요청
 → 서비스 워커 등록 (/firebase-messaging-sw.js)
 → getToken(VAPID 키) → 토큰
 → users/{uid}/fcmTokens/{토큰} 저장

[보내는 사람 브라우저]
알림 문서 생성(기존 코드) 커밋 성공
 → requestPush([알림 ID…])  ─────────▶  ID 토큰 검증
   (응답을 기다리지 않음)                   알림 문서 읽기 → 보낼 대상인지 판정
                                            pushedAt 기록 (중복 발송 방지)
                                            받는 사람 fcmTokens 조회
                                            messages:send  ────────────────▶  브라우저로 전달
                                            만료 토큰 삭제

[받는 사람 서비스 워커]
push 이벤트 → 보고 있는 탭이 없으면 시스템 알림 표시
알림 클릭 → link 열기 (이미 열린 탭이 있으면 그 탭으로 이동)
```

발송 방식은 **Next API 라우트(a안)**. Cloud Functions(b안)는 Blaze 요금제와 별도 배포가 필요해 택하지 않았다.
서버 크론(`/api/cron/close-expired-posts`)이 만드는 알림은 크론 안에서 같은 발송 함수를 바로 호출한다.

## 3. 토큰 저장

### 3-1. 위치

`users/{uid}/fcmTokens/{token}` — 문서 ID가 토큰이다 (같은 기기에서 다시 받아도 문서가 하나).

```ts
{ token: string, updatedAt: Timestamp }
```

`users` 문서 필드가 아니라 하위 컬렉션에 두는 이유: `users` 문서는 로그인 사용자 전체가 읽을 수 있다. 토큰은 본인만 읽고 쓰게 한다.

### 3-2. 등록 시점

- **마이페이지 → 계정 → 푸시 알림** 행을 눌러 켠다. 페이지 진입만으로 권한을 묻지 않는다 (브라우저가 거절 이력을 남기면 다시 물을 수 없음)
- 이미 권한이 허용된 사용자는 로그인할 때마다 `getToken`으로 토큰을 새로 받아 저장한다 (FCM 토큰은 바뀔 수 있음)
- 권한 상태별 표시

| `Notification.permission` | 표시 | 동작 |
|---|---|---|
| `default` | "꺼짐" | 누르면 권한 요청 → 허용 시 토큰 저장 |
| `granted` + 토큰 저장됨 | "켜짐" | — |
| `denied` | "차단됨 — 브라우저 설정에서 허용" | 누를 수 없음 |
| 미지원 브라우저 | "이 브라우저는 지원하지 않아요" | 누를 수 없음 |

### 3-3. 삭제 시점

- 로그아웃: 이 기기 토큰 문서를 지운 뒤 로그아웃한다 (공용 기기에서 다른 사람 알림이 오지 않게)
- 발송 시 FCM이 `UNREGISTERED`/`INVALID_ARGUMENT`(토큰 형식)로 응답한 토큰: 서버가 지운다

## 4. 발송 API — `POST /api/push`

### 4-1. 요청

```
Authorization: Bearer <Firebase ID 토큰>
{ "notificationIds": ["…", "…"] }   // 최대 50개
```

클라이언트는 `src/lib/services/pushService.ts`의 `requestPush(ids)`로 호출한다. 실패해도 무시한다 (인앱 알림은 이미 저장됐다).

### 4-2. 판정 (`src/lib/server/pushRules.ts`, 순수 함수)

알림 문서마다 아래를 모두 만족해야 보낸다.

| 조건 | 이유 |
|---|---|
| 문서가 존재 | — |
| `pushedAt` 없음 | 같은 알림을 두 번 보내지 않음 |
| `createdAt`이 2분 이내 | 오래된 알림을 다시 울리는 악용 방지 |
| `recipientId` ≠ 호출자 | 자기 자신에게는 보내지 않음 (알림 생성 규칙과 같음) |

`pushedAt`은 `updateTime` 사전 조건을 걸어 기록한다. 동시에 두 요청이 와도 하나만 성공해 한 번만 발송된다.

**호출자 검증의 한계:** 알림 문서에 보낸 사람 필드가 없어 "이 알림을 호출자가 만들었는지"는 확인하지 않는다.
대신 위 조건으로 *방금 생겨 아직 안 보낸 알림을 한 번 보내는 것*만 가능하다. 내용은 이미 받는 사람 인앱 알림에 있는 그대로라 악용 여지가 작다.

### 4-3. 메시지

데이터 메시지로 보내고 표시는 서비스 워커가 한다 (`notification` 페이로드를 쓰지 않음).

```json
{
  "message": {
    "token": "…",
    "data": { "title": "…", "body": "…", "link": "/chat/abc", "notificationId": "…" },
    "webpush": { "headers": { "Urgency": "high", "TTL": "86400" } }
  }
}
```

### 4-4. 인증

`firebase-admin`은 쓰지 않는다 (기존 `firestoreRest.ts`와 같은 이유 — 서버리스 ESM 문제).

| 할 일 | 방식 |
|---|---|
| ID 토큰 검증 | Google `securetoken` 공개 인증서로 `jsonwebtoken.verify` (RS256, `aud`=프로젝트 ID, `iss`=`https://securetoken.google.com/<프로젝트 ID>`) |
| Firestore 읽기·쓰기 | 기존 `firestoreRest.ts` |
| FCM 발송 | 서비스 계정 OAuth 토큰(`firebase.messaging` 범위)으로 HTTP v1 `messages:send` |

OAuth 토큰 발급은 `src/lib/server/googleAuth.ts`로 분리해 Firestore·FCM이 범위별로 캐시해 함께 쓴다.

## 5. 서비스 워커 — `public/firebase-messaging-sw.js`

Firebase SDK를 불러오지 않는 순수 서비스 워커다 (설정값을 주입할 필요 없음).

- `push`: 페이로드의 `data`를 꺼내, **보이는(visible) 앱 탭이 없을 때만** `showNotification`. 앱을 보고 있으면 인앱 알림 배지가 이미 실시간으로 갱신된다
- `notificationclick`: 알림을 닫고 같은 출처의 열린 탭이 있으면 포커스 후 `link`로 이동, 없으면 새 창
- 같은 `notificationId`는 `tag`로 묶어 중복 표시를 막는다

## 6. 알림 생성 위치별 발송

| 알림 종류 | 생성 위치 | 발송 |
|---|---|---|
| `new_message` | `useMessage.sendMessage` | `requestPush([id])` |
| `application_received` | `applicationService.applyToPost` | `requestPush([notiRef.id])` |
| `application_accepted` | `applicationService.acceptApplication` | 〃 |
| `application_rejected` | `applicationService.rejectApplication` | 〃 |
| `recruit_closed` (작성자) | `applicationService.closePendingApplications` | 커밋 후 생성한 ID 전부 |
| `recruit_deleted` | `recruitService.deleteRecruitPost` | 〃 |
| `recruit_closed` (크론) | `expiredPostsJob.closeExpiredPosts` | 서버에서 `sendPushForNotifications` 직접 호출 |

## 7. 보안 규칙

`users/{userId}` 규칙은 하위 컬렉션에 적용되지 않으므로 추가한다.

```
match /users/{userId}/fcmTokens/{tokenId} {
  allow read, delete: if isUser(userId);
  allow create, update: if isUser(userId)
    && request.resource.data.keys().hasOnly(['token', 'updatedAt'])
    && request.resource.data.token == tokenId;
}
```

`notifications`의 `pushedAt`은 서버(서비스 계정)만 쓴다. 클라이언트 생성 규칙의 `hasOnly` 목록에 없으므로 클라이언트가 미리 넣을 수 없다.

## 8. 환경 변수

| 이름 | 용도 |
|---|---|
| `NEXT_PUBLIC_FIREBASE_VAPID_KEY` | `getToken`의 웹 푸시 인증서 공개 키 (콘솔 → 프로젝트 설정 → 클라우드 메시징) |
| `FIREBASE_ADMIN_CLIENT_EMAIL`, `FIREBASE_ADMIN_PRIVATE_KEY` | 기존 값 재사용 (FCM 발송) |

Vercel에도 `NEXT_PUBLIC_FIREBASE_VAPID_KEY`를 추가해야 배포 환경에서 동작한다.
서비스 계정에 FCM 발송 권한(`cloudmessaging.messages.create`)이 필요하다. Firebase가 만든 `firebase-adminsdk` 계정에는 기본으로 있다.
