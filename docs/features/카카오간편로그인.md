# 카카오 간편로그인 기능명세서

> GitHub Issue: #21

## 1. 개요

현재 이메일/비밀번호 방식만 지원하는 인증에 카카오 간편로그인을 추가.
Firebase Authentication과 카카오 OAuth를 연동하여 기존 유저 시스템과 통합.

## 2. 인증 흐름

```
사용자 → 카카오 로그인 버튼(카카오 인가 페이지 링크) 클릭
  → 카카오 인가 후 /auth/kakao/callback?code=... 로 리다이렉트
  → 콜백 페이지가 POST /api/auth/kakao 로 인가 코드 전송
  → API Route에서:
    1. 카카오 서버에 액세스 토큰 요청
    2. 액세스 토큰으로 카카오 사용자 정보(닉네임) 조회
    3. 서비스 계정 키로 Firebase Custom Token(JWT) 서명 (`jsonwebtoken`)
    4. Custom Token과 { uid, nickname }을 클라이언트에 반환
  → 콜백 페이지에서 signInWithCustomToken으로 Firebase 인증 완료
  → users 문서가 없으면(첫 로그인) 클라이언트가 생성 (있으면 건드리지 않음)
  → 로그인 전에 보던 경로(없으면 홈)로 이동
```

카카오 JavaScript SDK는 쓰지 않는다. 로그인 버튼은 `src/components/AuthForm.tsx`의
`https://kauth.kakao.com/oauth/authorize?...` 링크다. (`layout.tsx`가 불러오는 카카오 SDK는 지도용이다.)

## 3. 카카오 개발자 설정 (사전 작업)

- Kakao Developers(https://developers.kakao.com) 앱 생성
- 플랫폼 > Web > 사이트 도메인 등록 (localhost:3000 + 배포 도메인)
- 카카오 로그인 활성화
- Redirect URI 등록: `{도메인}/auth/kakao/callback` (API 경로가 아니라 콜백 **페이지** 경로)
- 동의 항목: 닉네임 (필수). 프로필 이미지·이메일은 쓰지 않으므로 요청하지 않는다

## 4. 환경 변수

```env
NEXT_PUBLIC_KAKAO_REST_API_KEY= # 카카오 REST API 키 (인가 링크의 client_id, 토큰 요청에도 사용)
NEXT_PUBLIC_KAKAO_REDIRECT_URI= # {도메인}/auth/kakao/callback (인가 링크와 토큰 요청에 같은 값)
KAKAO_CLIENT_SECRET=            # 카카오 로그인 Client Secret (서버 토큰 요청용)

# Firebase 서비스 계정 (서버 사이드 Custom Token 서명용)
FIREBASE_ADMIN_CLIENT_EMAIL=
FIREBASE_ADMIN_PRIVATE_KEY=
```

지도용 `NEXT_PUBLIC_KAKAO_MAP_JS_KEY`는 로그인과 관계없다.

## 5. 구현 상세

### 5-1. 로그인 버튼

```
src/components/AuthForm.tsx
  KAKAO_AUTH_URL = https://kauth.kakao.com/oauth/authorize
    ?client_id=NEXT_PUBLIC_KAKAO_REST_API_KEY
    &redirect_uri=NEXT_PUBLIC_KAKAO_REDIRECT_URI
    &response_type=code
  → 떠나기 전에 돌아갈 경로(next)를 sessionStorage에 보관
```

### 5-2. API Route (서버 사이드)

```
POST /api/auth/kakao   (src/app/api/auth/kakao/route.ts)
  Request:  { code: string }  (인가 코드)
  Response: { token: string, user: { uid: string, nickname: string } }

처리 순서:
  1. 인가 코드 → 카카오 토큰 발급 (POST https://kauth.kakao.com/oauth/token)
  2. 액세스 토큰 → 사용자 정보 조회 (GET https://kapi.kakao.com/v2/user/me), 닉네임만 사용
  3. 닉네임을 닉네임 규칙에 맞게 다듬음 (toInitialDisplayName)
  4. 서비스 계정 키로 Custom Token 서명 (uid: "kakao_{카카오ID}")
```

API Route는 Firestore에 쓰지 않는다. 프로필 사진·이메일은 받지도 응답하지도 않는다.

### 5-3. 콜백 페이지

```
/auth/kakao/callback   (src/app/auth/kakao/callback/page.tsx)
  → URL에서 code 파라미터 추출 (error 파라미터면 "로그인을 취소했어요")
  → POST /api/auth/kakao 호출 → Custom Token 수신
  → signInWithCustomToken(auth, token)
  → users/{uid} 문서가 없으면 생성 (5-4)
  → sessionStorage에 보관한 경로(없으면 홈)로 이동
```

### 5-4. Firestore 유저 데이터

```typescript
// 첫 로그인 때 콜백 페이지가 저장하는 users 문서
{
  uid: "kakao_123456789",
  displayName: "카카오닉네임",   // 닉네임 규칙에 맞지 않으면 "사용자"
  provider: "kakao",
  createdAt: serverTimestamp(),
}
```

users 문서는 로그인한 사용자 누구나 읽을 수 있으므로 이메일·프로필 사진은 저장하지 않는다.
보안 규칙(`firestore.rules`의 `userKeys()`)이 가입 시 `uid, displayName, provider, createdAt` 외의 키를 거부한다.
예전에 저장된 `email`, `profileImage`는 `scripts/cleanup-user-pii.mjs`로 지운다.

## 7. User 타입 변경

```typescript
export interface User {
  uid: string;
  displayName: string;
  provider?: "email" | "kakao";
  createdAt: Date;
}
```

이메일이 필요한 화면(마이페이지 등)은 Firebase Auth의 `user.email`을 쓴다. 카카오 사용자는 `null`이다.

## 8. 영향 범위

| 파일 | 변경 내용 |
|------|-----------|
| `src/app/api/auth/kakao/route.ts` | API Route - 토큰 교환 + Custom Token 생성 (신규) |
| `src/app/auth/kakao/callback/page.tsx` | 콜백 페이지 - 로그인 완료 + 첫 로그인 시 users 문서 생성 (신규) |
| `src/app/login/page.tsx` | 카카오 로그인 버튼 추가 |
| `src/app/signup/page.tsx` | 카카오 로그인 버튼 추가 |
| `src/components/AuthForm.tsx` | 카카오 인가 링크 버튼 추가 |
| `src/types/index.ts` | User 타입에 provider 추가 |
| `.env.local` | 카카오 + Firebase 서비스 계정 환경 변수 |

## 9. 의존성

```
jsonwebtoken  — 서버 사이드 Custom Token(RS256 JWT) 서명용
```

> 초기에는 `firebase-admin`을 사용했으나, 의존 패키지 `jose`가 ESM 전용이라 Vercel 서버리스 런타임에서 `ERR_REQUIRE_ESM`이 발생해 `jsonwebtoken`으로 교체했다.

## 10. 주의 사항

- 카카오 CI/BI 가이드 준수 (버튼 색상 #FEE500, 로고 사용 규정)
- 카카오 계정과 기존 이메일 계정은 별도 계정으로 관리 (추후 연동 기능은 별도 이슈)
- 서비스 계정 Private Key는 환경 변수로만 관리, 절대 코드에 포함 금지
