# 모집 자동 마감 기능명세서

> GitHub Issue: #20

## 1. 개요

경기 날짜와 시간이 지난 모집글을 자동으로 마감(closed) 처리하는 기능.
현재는 작성자가 수동으로 마감하거나, 정원이 찬 경우에만 자동 마감됨.

## 2. 만료 판별 기준

- `RecruitPost.date` (예: "2026-09-22") + `RecruitPost.time` (예: "18:00")을 조합하여 경기 시작 시각 생성
- 현재 시각 >= 경기 시작 시각이면 **만료**로 판별

## 3. 자동 마감 처리 흐름

### 3-1. 목록 (useRecruitPosts)

```
useRecruitPosts 훅
  → onSnapshot으로 open 게시글 수신
  → selectPostsToClose()로 마감 대상 선별
    (status가 open · 경기 시간 경과 · 이번 세션에서 아직 시도하지 않음)
  → 대상마다 closeRecruitPost(postId) 호출 후 id를 시도 기록에 추가
  → 로컬 상태에서도 만료 글을 즉시 필터링
```

제약:

- **로그인 사용자만 쓴다.** 보안 규칙이 `signedIn()`을 요구하므로 비로그인 세션은 화면에서 숨기기만 한다.
- **인증 확정 후에만 쓴다.** 훅이 받는 `auth.ready`가 false면 구독 자체를 시작하지 않는다.
- **세션당 글마다 1회만 쓴다.** `useRef`에 시도한 postId를 기록해, 동시 접속자나 반복 스냅샷으로 같은 글에 쓰기가 몰리는 것을 억제한다.
- **쓰기 필드는 `status`와 `updatedAt` 둘뿐이다.** 보안 규칙의 `changedOnly(['status','updatedAt'])`를 만족해야 한다.
- **실패는 무시한다.** `permission-denied`가 목록 렌더를 깨뜨리지 않도록 `.catch(() => {})`로 흘린다.

목록 쿼리가 `status == 'open'`이므로 마감된 글은 다음 스냅샷에서 빠진다 (재트리거 루프가 생기지 않는다).

### 3-2. 모집글 상세 페이지

```
recruit/[postId]/page.tsx
  → 페이지 로드 시 만료 여부 체크
  → 만료된 글이면 자동 마감 처리 + "마감된 모집입니다" 표시
  → 참가 신청 버튼 비활성화
```

### 3-3. 대기 신청 정리 (작성자 지연 처리)

자동 마감은 **아무 로그인 사용자**가 수행하지만, 보안 규칙상 신청 문서는 **작성자만** 바꿀 수 있다.
그래서 자동 마감된 글에는 대기 신청이 `pending`으로 남는다. 권한이 있는 작성자가 자기 글을 열 때 정리한다.

```
useMyRecruitPosts (내 모집글) / recruit/[postId] (작성자 본인)
  → selectPostsToCleanup()으로 정리 대상 선별
    (status가 closed · applicantIds 수 > acceptedCount · 이번 세션에서 아직 시도하지 않음)
  → closePendingApplications(postId, title)
    = 대기 신청을 closed로 변경 + recruit_closed 알림 전송 + applicantIds에서 제외
```

대기 신청 잔여 판단에 추가 읽기가 필요 없다 — `applicantIds`는 대기 + 수락 신청자이고
`acceptedCount`는 수락 인원이므로, 둘의 차이가 곧 대기 인원이다
(거절·취소·마감 처리된 신청자는 `applicantIds`에서 빠진다).

정리 쓰기가 반영되기 전에도 신청 목록에서는 `displayApplicationStatus`로 대기 신청을 "마감"으로
표시하고 수락·거절 버튼을 숨긴다. 마감된 글은 수락이 거부되기 때문이다.

마감된 글은 `applicantIds`가 `acceptedCount`와 같아지므로 정리 후 다시 대상이 되지 않고,
세션당 글마다 1회만 시도하므로(`useRef`) 재트리거 루프가 생기지 않는다.

## 4. 과거 날짜 선택 방지

- 글 작성(/create) 페이지의 날짜 입력 필드에 `min` 속성 추가
- 오늘 이전 날짜는 선택 불가
- 수정 페이지에서도 동일 적용

## 7. 예외 처리

- 네트워크 에러 시 로컬에서만 마감 표시, Firestore 업데이트 실패는 무시
- 쓰기 실패한 글은 같은 세션에서 재시도하지 않는다 (시도 기록에 남으므로). 새로고침 또는 다른 사용자의 접속 시 다시 시도된다
- time 값이 없는 경우 해당 날짜 23:59으로 간주

## 8. 한계

클라이언트가 목록이나 상세를 열 때만 마감되므로, 아무도 접속하지 않으면 만료 글이 `open`으로 남는다.
완전한 보장이 필요하면 서버 측 주기 작업(Vercel Cron 등)이 필요하다 — `docs/개선작업목록.md` 참고.

대기 신청 정리도 같은 성질이다. 작성자가 자기 글을 한 번도 열지 않으면 대기 신청은 `pending`으로 남고
`recruit_closed` 알림도 그때 전송된다. 신청 문서는 작성자만 바꿀 수 있어서, 신청자 화면에서는
모집글을 함께 읽지 않는 한 파생 표시를 할 수 없다.

경기 시간이 지난 글은 `assertCanReopen`에서 재오픈이 막히므로, 이 경로에서 `applicantIds` 정리는
재신청 가능성 때문이 아니라 대기 신청 잔여를 판단하는 기준을 유지하기 위한 것이다.
