## 상세

### 1. 참가 신청 트랜잭션
- `applyToPost`가 매번 새 신청 문서를 만들어, 연타·여러 탭에서 같은 유저의 신청이 중복 생성될 수 있음
- `acceptApplication`이 상태 변경 → 인원 증가 → 개수 조회 → 마감을 개별 쓰기로 처리해 동시 수락 시 정원 초과, 마감된 글에서도 수락 가능
- 중간 단계 실패 시 신청 문서와 모집글 `applicantIds`가 어긋남
- 해결: `runTransaction`으로 묶고 트랜잭션 안에서 모집글 상태·정원·중복 여부를 검증

### 2. 보안 규칙
- `firestore.rules`가 저장소에 없음
- 신청자가 남의 모집글(`applicantIds`)을 직접 수정하고, 다른 유저의 알림을 클라이언트에서 생성하는 구조라 규칙이 느슨할 가능성이 큼
- 해결: 규칙 파일을 저장소에 추가하고 역할별 수정 가능 필드를 제한 (예: 신청자는 `applicantIds`에 자기 uid만 추가·제거)
- 기존 콘솔 규칙의 `match /{document=**}` 와일드카드가 로그인 사용자에게 전체 읽기/쓰기를 허용해, 알림·유저 규칙이 사실상 무력화되어 있었음
- 검증: `npm run test:rules` (Firestore 에뮬레이터, Java 필요)
- 남은 점: `applications`는 모집글 상세에서 postId로 조회하므로 로그인 사용자 전체 읽기 허용. `users` 문서의 `email`도 로그인 사용자 전체에 읽힘
- 주의: 시드 스크립트(`src/lib/seed`)는 다른 유저 명의로 글을 만들므로 새 규칙에서는 클라이언트로 실행 불가

### 3. 모집글 삭제 시 연관 데이터
- `deleteRecruitPost`가 모집글만 삭제해 신청 문서·알림이 남음 → 신청 내역에 없는 글이 남고, 알림 클릭 시 404
- 해결: 연관 문서를 함께 삭제하거나 신청을 "삭제된 모집" 상태로 전환
- 처리: 모집글 삭제와 같은 배치에서 신청 문서 삭제, 대기·수락 신청자에게 `recruit_deleted` 알림 전송
- 규칙: 모집글이 없는(같은 배치에서 삭제되는) 경우에만 작성자의 신청 문서 삭제 허용
- 남은 점: 이 변경 이전에 삭제된 글의 신청 문서(고아 데이터)는 그대로 남아 있음. 기존 알림의 링크는 상세 페이지의 "게시글을 찾을 수 없어요" 화면으로 연결됨

### 4. 만료 글 자동 마감
- `docs/features/모집자동마감.md`는 목록에서 만료 글 발견 시 `closed`로 저장한다고 하지만, `useRecruitPosts`는 화면에서 숨기기만 함 (상세 페이지 진입 시에만 저장)
- 해결: 목록에서도 Firestore에 마감을 저장하도록 구현. 마감 대상 선별은 `selectPostsToClose`(`src/lib/utils/recruitExpiry.ts`) 순수 함수로 분리하고 단위 테스트 추가
- 중복 쓰기는 `useRef`에 시도한 postId를 기록해 세션당 글마다 1회로 제한. 보안 규칙(`firestore.rules` 66-71행)이 경기 시간이 지난 글의 `status`/`updatedAt` 변경만 허용
- 남은 점: 아무도 접속하지 않으면 여전히 `open`으로 남는다. 완전한 보장은 서버 측 주기 작업(Vercel Cron 등)이 필요

### 5. 마감·재오픈 후속 처리
- 마감 시 대기 중인 신청이 그대로 남고 신청자에게 알림이 없음
- 정원이 찬 상태에서도 재오픈 가능

### 6. 페이지네이션
- 모집글·채팅 메시지·알림 쿼리에 `limit`이 없어 전체를 실시간 구독
- 해결: 커서 기반 페이지네이션 또는 무한 스크롤
